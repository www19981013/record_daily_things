# 精力恢复记事本工具 — 设计文档

日期：2026-08-13
状态：已批准（待实现）

## 1. 背景与目标

用户是"计划焦虑人"：列计划会引发焦虑，但记录已完成的事能带来成就感。本工具提供一个**只记录、不计划、不评价**的记事本，并基于 AI 自动形成每周/每月小结（事实性归类汇总）。

核心原则：

- **只记录已完成的事，不列计划。**
- **不对任何事做评价、评分、评级，只记录。**
- **基于 AI 自动形成每周小结和每月小结。**
- 目前仅本地部署，未来以网页服务形式部署至云服务器，需做技术预留。

## 2. 已确认的决策

| 维度 | 决定 |
|---|---|
| 使用模式 | 仅个人使用，单用户，无账号/登录 |
| 记录形式 | 纯文字 |
| 分类 | 不加标签，由 AI 在生成小结时自动归类 |
| AI 模型 | 可选配置。云端 API 优先（默认 DeepSeek，OpenAI 兼容接口），通过环境变量配置；抽象模型接口预留切换（如本地 Ollama）。未配置模型时，小结退化为纯拼接 |
| 小结触发 | 手动触发（点击"生成"按钮），AI 自动起草内容 |
| 技术方案 | 方案 B：FastAPI 后端 + 轻量前端 |
| 前端框架 | Vue 3（默认） |
| 数据库 | SQLite（本地），预留 PostgreSQL（上云） |

## 3. 整体架构

三层结构，职责清晰、可独立测试：

```
浏览器 (Vue 3 SPA)
   │  REST / JSON
   ▼
FastAPI 后端
   ├─ entries 路由（记录 CRUD）
   ├─ summaries 路由（小结生成/查看）
   ├─ llm 模块（模型抽象 + prompt 模板）
   └─ db 模块（SQLAlchemy + SQLite）
   ▼
SQLite（预留 PostgreSQL）  +  云端 LLM API（预留切换本地）
```

- 前端为单页应用，纯 API 驱动，与后端完全解耦；未来上云只改后端部署方式，前端基本不动。
- 单用户、无会话/登录，数据不带用户标识。

## 4. 数据模型

| 表 | 字段 | 说明 |
|---|---|---|
| `entries` | id, content, created_at | 一条"已完成的事"，纯文字 |
| `summaries` | id, period_type, period_start, period_end, content, created_at | 已生成的小结，缓存避免重复调 AI |

- `period_type` 取 `weekly` / `monthly`。
- 周期边界：周以周一为起点，月为自然月。
- 小结一旦生成即落库；重复打开直接读缓存，不重复调用 AI。若周期内新增了记录，用户可再次点击生成以覆盖刷新小结。

## 5. 核心模块与数据流

### 5.1 记录
输入「今天完成了什么」→ `POST /entries` → 存库。纯本地操作，**不依赖 AI**（AI 不可用不影响记录）。

### 5.2 小结
点击「生成本周/本月小结」→ 后端拉取该周期的所有 entries →
- 若已配置大模型：拼 prompt → 调 LLM → 得到归类小结。
- 若未配置大模型：跳过 LLM，直接将周期内条目按日期拼接成小结。

结果存 `summaries` → 返回展示。

### 5.3 AI 抽象层
- 定义 `BaseLLM` 接口：`generate(prompt: str) -> str`。
- 默认实现 `OpenAICompatibleLLM`：从环境变量读取 `api_key`、`base_url`、`model`，指向 DeepSeek/通义等兼容接口。
- 预留 `OllamaLLM` 本地实现。
- 未配置模型（环境变量缺失）时，小结走纯拼接降级路径（见 5.2）。
- 切换模型只改配置，不改业务代码。

## 6. 「不评价」的硬约束

本工具的灵魂，需在两层强制保证：

- **prompt 模板层**：明确指令"只做事实性归类与汇总，禁止任何评价"，并附**禁用词表**（如：优秀/很棒/进步/需要改进/建议你/继续保持等）。
- **UI 层**：小结只展示归类整理后的条目，不出现评分、星级、等级、进度条等元素。

## 7. 错误处理

- 未配置大模型是合法状态：小结自动走纯拼接降级路径，不算错误。
- LLM 调用失败（超时、网络、key 无效）→ 返回友好提示「小结生成失败，请稍后重试」，记录功能不受影响。

## 8. 测试

- 后端 API 单测：pytest + 临时 SQLite，覆盖 entries CRUD、summary 生成与缓存。
- LLM 层用 mock：测试小结逻辑与 prompt 内容，不真实调用 API。
- 关键用例：验证生成的 prompt 包含"不评价"约束词。

## 9. 部署预留

- 数据层经 SQLAlchemy 抽象，本地 SQLite → 云端 PostgreSQL 仅改连接串。
- 前端与后端解耦，上云时后端以 uvicorn + 反向代理部署即可。
- 单用户；未来若需多人，可再加登录/鉴权与数据隔离（当前不做）。

## 10. 范围外（YAGNI）

- 不做登录/鉴权系统。
- 不做图片/附件、富文本、Markdown。
- 不做标签/手动分类。
- 不做提醒、推送、计划功能。
- 不做评分/评级/统计图表。
